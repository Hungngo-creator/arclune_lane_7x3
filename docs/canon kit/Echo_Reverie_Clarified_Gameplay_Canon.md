# ECHO REVERIE — CLARIFIED GAMEPLAY CANON
## Gameplay-logic clarification before Tag / Primitive / Contract normalization

**Character:** Echo Reverie  
**Source:** Echo in the myth of Narcissus, especially the Ovidian motif of being unable to initiate speech and only repeating what was last spoken.  
**Class:** Mage  
**Element:** Not specified in this source.  
**Status:** Clarified Gameplay Canon — ready for semantic normalization after the current canonical architecture is up to date.  
**Scope:** Turn-based mode first.  
**Important:** This document defines **gameplay behavior and semantic intent**. It does **not** yet assign new Functional Tags, Primitive IDs, Contract IDs, or Kernel implementation.

---

# 0. PURPOSE

Echo Reverie is intended as a difficult Pilot-Normalization character.

The design identity is:

> **Repeat the last action / last word / last effect.**

The kit deliberately combines:
- repeated damage;
- Action Identity memory;
- autonomous Natural Action restriction;
- Rage readiness;
- high AE consumption;
- shield admission by Authority;
- multiple independent Shield pools;
- shield-to-damage scaling;
- shield-to-Max-HP conversion;
- child Skill execution from Ultimate.

The workflow is:

```text
Original Echo kit
→ this Clarified Gameplay Canon
→ Terminology normalization
→ Architecture Impact Matrix
→ existing Tag / Schema / Primitive / Contract mapping
→ only then consider generic architecture gaps
```

Do not create `ECHO_*` architecture abstractions merely because this Character is complex.

# 1. GLOBAL SYSTEM CONTEXT USED BY ECHO

## 1.1 Natural Action

A Natural Action is the Action opportunity granted by SSI to the Character.

A Natural Action may execute:
- Basic Attack;
- Skill;
- Ultimate,

subject to legality, resources, restrictions, and Character-specific behavior.

Follow-up / Counter / Reaction / Forced Action / child Action are not Natural Actions unless explicitly reclassified by a special rule.

## 1.2 Global Rage readiness

Each Character has its own:

```text
Current Rage
Max Rage
```

When:

```text
Current Rage >= Max Rage
```

the Character is Rage-ready for Ultimate, provided no other rule/effect prevents Ultimate use.

Lower Max Rage is generally advantageous because less Rage is required to become Ultimate-ready.

## 1.3 Deck deployment and Rage

Successful deployment specifically from Deck to Battlefield applies:

```text
DEPLOY_FROM_DECK
→ Current Rage = Max Rage
```

This is separate from generic field entry.

Revive, Arena return, Rebirth, or other field-entry cases do not automatically receive full Rage merely because they enter the field.

## 1.4 AE regeneration by Class

After a Character actually completes one of its own Natural Actions, its Side/team gains AE according to the Character's Effective Class:

```text
Support   = +10 AE
Mage      = +7 AE
Summoner  = +7 AE
Warrior   = +5 AE
Tanker    = +5 AE
Ranger    = +5 AE
Assassin  = +3 AE
```

Basic / Skill / Ultimate performed as the Natural Action all generate the same AE amount for that Class.

If CC causes the Character to lose the Natural Action opportunity and no Natural Action is actually performed:

```text
AE gain = 0
```

Follow-up / Counter / Reaction / Forced Action / child Action:

```text
AE gain = 0
```

Echo is a Mage, therefore:

```text
Echo completed Natural Action
→ Side +7 AE
```

unless a later global rule changes his Effective Class or modifies AE generation.

## 1.5 Ordering of Echo's linked costs vs AE regeneration

Echo is intentionally resource-negative and should not self-fund his linked passive costs with the AE generated by the same Natural Action.

For Echo's clarified gameplay flow:

```text
Natural Action effects
→ linked damage / passive-repeat outcomes
→ Echo linked passive settlements that belong to that Natural Action
→ Natural Action completes
→ AE_ACTION_REGEN_BY_CLASS grants +7 AE
```

Therefore, Skill 1 / Skill 3 costs tied to the current Natural Action must be payable **before** Echo receives the +7 AE generated by completion of that same Natural Action.

This preserves the intended design that Echo needs team AE support.

# 3. PASSIVE — REVERBERATED DAMAGE

Echo has a symmetric repeat-damage passive.

It listens to two directions:

1. enemy damage successfully causing Actual HP Damage to Echo;
2. Echo damage successfully causing Actual HP Damage to an enemy.

The repeat is based on **Actual HP Damage**, not raw packet value.

## 3.1 Incoming repeat

When an enemy causes qualifying Actual HP Damage to Echo:

```text
Original qualifying Actual HP Damage = D
Repeat True Damage = 50% × D
```

The repeated True Damage targets Echo himself.

Example:

```text
Enemy attack resolves
→ Echo actually loses 100 HP

Echo passive:
→ 50 True Damage to Echo
```

The repeated True Damage:
- is attributed to Echo;
- is treated as Echo damaging Echo;
- is not attributed to the original enemy;
- carries no copied secondary effect;
- is not a Natural Action;
- does not grant the original enemy benefits from that repeated damage.

True Damage still follows the global rule that True Damage does not automatically bypass Shield.

## 3.2 Outgoing repeat

When Echo causes qualifying Actual HP Damage to an enemy:

```text
Original qualifying Actual HP Damage = D
Repeat True Damage = 50% × D
```

to that same enemy.

The repeated True Damage:
- Damage Attribution = Echo;
- contains damage only;
- does not copy Buff/Debuff/DoT/Mark/stack/CC or other attached effects;
- is not a Natural Action.

For multi-target damage, evaluate independently per enemy.

Example:

```text
Echo causes 200 Actual HP Damage to A
Echo causes 80 Actual HP Damage to B

Passive:
A receives 100 True Damage
B receives 40 True Damage
```

## 3.3 No recursion

Damage generated by Echo's repeat passive cannot trigger the repeat passive again.

Hard rule:

```text
original qualifying Damage
→ one repeat True-Damage layer
→ stop
```

This applies both to self-repeat and enemy-repeat.

If two Echo Reveries oppose each other, passive-generated repeat damage from one Echo does not recursively activate the other Echo's repeat passive.

## 3.4 DoT exclusion

DoT ticks do **not** trigger the 50% repeat passive.

Example:

```text
Enemy Skill:
initial hit = 100 Actual HP Damage
applies DoT

DoT tick = 20 Actual HP Damage
```

Result:

```text
initial hit
→ 50 True Damage repeat

DoT tick
→ no repeat
```

Passive-generated repeat damage is also excluded.

# 4. PASSIVE — ACTION-FORM MEMORY

Echo remembers the latest qualifying **incoming damaging Action form** before his next actually performed Natural Action.

Remembered categories:

```text
BASIC_ATTACK
SKILL
ULTIMATE
```

The memory is based on Action Identity / Action ancestry, not damage type.

## 4.1 Memory window

Legacy wording such as “Echo's Turn Boundary” must not be used.

Canonical `TURN_BOUNDARY` is global SSI.

Echo instead uses an actor-specific memory window:

```text
after Echo's last actually completed Natural Action
→ until Echo's next actually performed Natural Action
```

Every qualifying incoming damaging Action in this window can overwrite the current record.

Only the **latest qualifying** record is retained.

Example:

```text
incoming Basic damages Echo
→ memory = BASIC_ATTACK

incoming Ultimate damages Echo
→ memory = ULTIMATE

incoming Skill damages Echo
→ memory = SKILL

incoming DoT damages Echo
→ ignored

incoming passive damage damages Echo
→ ignored
```

At Echo's next actually performed Natural Action:
> restriction reads `SKILL`.

## 4.2 What can update memory

An incoming damage event may update memory if:

1. it causes Echo Actual HP Damage;
2. it has qualifying Action Identity/ancestry;
3. the relevant form is Basic Attack, Skill, or Ultimate;
4. it is not excluded as DoT/passive/anonymous system damage.

The source Action does **not** need to be a Natural Action.

Qualifying Follow-up / Counter / Reaction / Forced / child Actions may update memory if their Action ancestry is defined.

## 4.3 Enhanced Basic

An enhanced Basic Attack is still recorded as:

```text
BASIC_ATTACK
```

Enhancement does not change Action Identity.

## 4.4 Root and child Action ancestry

Example:

```text
enemy root Action = ULTIMATE
→ child SKILL
→ child Skill causes Actual HP Damage to Echo
```

Echo records:

```text
primary remembered form = ULTIMATE
fallback damaging form  = SKILL
```

The root Action identity wins as primary restriction.

# 5. PASSIVE — NEXT NATURAL ACTION RESTRICTION

Echo's memory restricts the **form** of his next actually performed Natural Action.

It does not force Echo to target the Character that damaged him.

Echo remains under normal SSI and normal target-selection rules.

## 5.1 BASIC memory

If:

```text
memory = BASIC_ATTACK
```

Echo's next Natural Action uses Basic Attack, subject to ordinary legality.

## 5.2 SKILL memory

If:

```text
memory = SKILL
```

Echo attempts an eligible damaging Skill.

If that Skill cannot legally/payably be used, including insufficient AE:

```text
fallback = BASIC_ATTACK
```

Echo does not automatically lose the Natural Action.

## 5.3 ULTIMATE memory

If:

```text
memory primary = ULTIMATE
```

Echo attempts Ultimate first.

If:

```text
Current Rage >= Max Rage
AND Ultimate is legal
```

Echo uses Ultimate.

If Ultimate is unavailable, Echo attempts the remembered damaging child form if one exists.

Example:

```text
enemy ULTIMATE
→ child SKILL damages Echo

memory:
primary = ULTIMATE
fallback = SKILL

Echo next Natural Action:

if Ultimate legal + Rage-ready
→ Ultimate

else if Skill legal + payable
→ Skill

else
→ Basic Attack
```

If the damaging Ultimate has no qualifying child Basic/Skill identity:

```text
Ultimate unavailable
→ Basic Attack fallback
```

## 5.4 CC does not consume memory

If Echo's next SSI opportunity is lost to CC and he does not actually perform a Natural Action:

> memory is not consumed or reset.

Example:

```text
memory = SKILL

next Echo SSI opportunity:
Stunned
→ no Action

memory remains SKILL
```

The next actually performed Natural Action still obeys the Skill restriction.

## 5.5 Memory reset

After Echo actually performs the Natural Action governed by the current memory:

> the memory is cleared.

A new memory window begins.

## 5.6 No memory

If Echo has no qualifying remembered Action form:

> this passive imposes no action-form restriction.

Echo still acts autonomously rather than requiring the Leader/player to manually choose Basic/Skill/Ultimate.

Exact unrestricted Skill-vs-Basic choice follows the normal autonomous action-selection policy and is not invented here.

However:

```text
if Echo is Rage-ready
and Ultimate is legal
→ Ultimate has normal automatic priority
```

Therefore, on Deck deployment:
- Echo enters with full Rage;
- no enemy Action has yet been remembered;
- at his first Natural Action, Ultimate is used normally if legal.

# 6. SHIELD ADMISSION — AUTHORITY

Echo rejects low-Authority external Shield.

Legacy wording such as “Shield with Quy Tắc Tag” must not be used.

Authority is not a Functional Tag.

An external Shield is admitted only if its relevant rule/effect Authority is at least:

```text
QUY TẮC
```

Therefore:
- Normal external Shield → rejected;
- Pháp Tắc external Shield → rejected;
- Quy Tắc external Shield → accepted;
- Axiom external Shield → accepted.

If a special Authority conflict exists, normal Authority adjudication applies.

# 7. TWO INDEPENDENT SHIELD POOLS

Echo has two independent Shield categories.

## 7.1 External Eligible Shield Pool

Contains eligible Shield from outside Skill 1.

Cap:

```text
100% of Echo Current Max HP
```

## 7.2 Skill 1 Shield Pool

Contains Shield produced by Echo Skill 1.

Cap:

```text
100% of Echo Current Max HP
```

Caps are independent.

Echo can therefore theoretically hold:

```text
100% Max HP external Shield
+
100% Max HP Skill 1 Shield
```

before other special rules.

Excess gain above the relevant pool cap is discarded.

## 7.3 Absorption priority

Incoming damage consumes:

```text
1. External Eligible Shield Pool
2. Skill 1 Shield Pool
3. HP
```

External Shield is consumed first.

Within ordinary external contributions, canonical Standard Shield source-ledger/proportional depletion remains in force unless a specific accepted Shield has its own special Contract.

# 8. SKILL 1 — PASSIVE DAMAGE CONVERSION

Skill 1 is passive/automatic.

It does not consume a Natural Action.

For each Echo Natural Action, aggregate the **Actual HP Damage dealt to enemies by Echo's repeat-passive True Damage that belongs to the outcome of that Natural Action**.

Let:

```text
P = total qualifying passive-repeat Actual HP Damage to enemies
```

Incoming self-repeat damage does not count.

## 8.1 Conversion

If:

```text
P > 0
```

Skill 1 attempts one settlement for that Natural Action.

Total conversion = 45% of P:

```text
Heal Echo          = 22.5% × P
Skill 1 Shield gain = 22.5% × P
```

Example:

```text
P = 1000

Heal   = 225
Shield = 225
```

## 8.2 AE cost

Normal Skill 1 settlement costs:

```text
10 AE
```

If:

```text
P = 0
```

no activation and no AE cost.

If:

```text
P > 0
but Side AE < 10
```

then:
- no Heal;
- no Shield;
- no AE is paid;
- P does not carry into another Natural Action.

## 8.3 Heal

Skill 1 heals Echo himself.

Any Overheal is discarded.

Overheal does not become more Shield.

## 8.4 Shield

Skill 1 Shield gain is added to the Skill 1 Shield Pool.

Cap:

```text
100% Echo Current Max HP
```

Overflow is discarded.

Skill 1 Shield has no duration timer.

It persists until:
- absorbed;
- removed by another valid effect;
- converted by Skill 3;
- or battle/lifecycle rules remove it.

# 9. SKILL 2 — FULL-FIELD DAMAGE

Skill 2 is an active Skill.

Cost:

```text
30 AE
```

Targets:

```text
all eligible enemies currently on the Battlefield
```

This is genuine full-field Area Resolution.

All selected enemies resolve simultaneously.

## 9.1 Damage formula

Snapshot Echo's current total Shield:

```text
Total Shield
=
External Eligible Shield Pool
+
Skill 1 Shield Pool
```

Per enemy:

```text
Physical component
= 145% Echo ATK

Will component
= 175% Echo WIL
+ 15% Echo current total Shield
```

The Shield-derived term is Will Damage.

It is not True Damage.

## 9.2 Skill 2 → passive interaction

For each enemy that loses Actual HP from Skill 2:

```text
Skill 2 Actual HP Damage
→ Echo repeat passive
→ 50% of that Actual HP Damage as True Damage
```

The repeat is evaluated per enemy.

Passive repeat damage belonging to this Natural Action can contribute to Skill 1's P aggregate.

# 10. SKILL 3 — TRUE-SELF DEATH CONVERSION

Skill 3 is passive/automatic.

It does not consume a Natural Action.

During each actually performed Echo Natural Action, observe qualifying:

```text
DEATH_CONFIRMED
```

on enemy targets that possess a True Self.

If at least one qualifying enemy True Self receives DEATH_CONFIRMED as an outcome attributable to that Echo Natural Action:

> Skill 3 may activate once for that Natural Action.

The number of qualifying deaths does not increase activation count within that Action.

Example:

```text
1 qualifying True Self dies
→ one Skill 3 activation attempt

5 qualifying True Selves die
→ still one Skill 3 activation attempt
```

## 10.1 Linked passive kills count

If Echo's root Natural Action damages a target and Echo's linked repeat-passive True Damage from that same Action later causes the qualifying DEATH_CONFIRMED:

> that death still qualifies.

The passive outcome remains part of the root Natural Action's attributable outcome.

## 10.2 Attribution requirement

Temporal coincidence is insufficient.

The qualifying DEATH_CONFIRMED must be attributable to the outcome of Echo's Natural Action.

Unrelated deaths during the same interval do not qualify.

## 10.3 AE cost and battle cap

Each successful activation costs:

```text
30 AE
```

Maximum successful activations:

```text
10 per battle
```

If AE is insufficient:
- no activation;
- no Shield removal;
- no Max HP increase;
- no successful-activation count consumed.

## 10.4 Shield → Max HP conversion

Let:

```text
S = current total Shield from all Echo Shield sources/pools
```

Successful Skill 3 activation converts:

```text
50% × S
```

from Shield into Max HP at 1:1.

Conceptually:

```text
removed Shield = 50% current total Shield
Max HP gain    = same amount
```

The 50% removal is applied proportionally across Echo's current Shield pools/contributions.

Example:

```text
External Shield = 600
Skill 1 Shield  = 400
Total S         = 1000

remove 500 Shield
Max HP +500
remaining Shield total = 500
```

## 10.5 Current HP

Max HP gained from Skill 3 does not Heal Echo.

Current HP remains unchanged in absolute value.

Example:

```text
Current HP = 700
Max HP     = 1000

Skill 3 converts 500 Shield

Max HP → 1500
Current HP remains 700
```

## 10.6 Zero Shield

If:

```text
S = 0
```

Skill 3 does not successfully activate.

Therefore:
- no 30 AE;
- no activation count consumed.

## 10.7 Duration

Max HP gained by Skill 3 persists for the battle unless a later explicit lifecycle rule removes/resets it.

It is not automatically removed merely because Echo temporarily leaves the current field.

The 0–10 successful-activation counter is also battle-scoped.

# 12. ULTIMATE

Ultimate is a root Action with:

```text
root Action Identity = ULTIMATE
```

It performs:

> cast Skill 2 once with Skill 2 AE Cost overridden to 0.

This child execution of Skill 2:
- is not a second Natural Action;
- retains child identity `SKILL`;
- remains under root ancestry `ULTIMATE`.

## 12.1 Ancestry interaction

If an opposing Echo receives Actual HP Damage from this Ultimate's child Skill 2:

```text
primary remembered form = ULTIMATE
fallback damaging form  = SKILL
```

## 12.2 Next two Natural Actions

After Ultimate resolves:

```text
next 2 actually performed Echo Natural Actions:
Skill 1 AE Cost = 0
```

This is a Natural-Action duration/window.

It is not “two free Skill 1 procs stored indefinitely”.

### Window consumption

Each of the next two actually performed Echo Natural Actions consumes one window step even if Skill 1 does not proc.

Example:

```text
Ultimate resolves

next Echo Natural Action #1:
P = 0
→ no Skill 1 proc
→ first free window step still consumed

next Echo Natural Action #2:
P > 0
→ Skill 1 proc costs 0
→ second step consumed

window ends
```

A CC-lost SSI opportunity with no actual Natural Action:
> does not advance this window.

# 13. DEPLOYMENT FLOW

When Echo is successfully deployed from Deck:

```text
1. Deployment commits
2. Echo enters Battlefield
3. DEPLOY_FROM_DECK fills Current Rage to Max Rage
4. Echo has no Action-form memory yet
5. wait for Echo's first Natural Action
6. if Echo actually performs it:
   Ultimate has normal automatic priority because Echo is Rage-ready,
   provided Ultimate is legal
7. Ultimate invokes Skill 2 with 0 AE Cost
8. outgoing passive repeats may occur
9. Skill 3 may settle if eligible/payable
10. Skill 1 may settle if eligible/payable/free
11. Echo Natural Action completes
12. Mage AE regeneration grants +7 AE
```

Echo does not need a special non-Natural auto-cast-on-deploy event.

Full Rage plus normal automatic Ultimate priority is enough.

# 14. SKILL 1 / SKILL 3 SAME-ACTION ORDER

When both Skill 3 and Skill 1 are eligible from the same Echo Natural Action:

```text
Skill 3 Shield→Max-HP conversion resolves first
then
Skill 1 Heal/Shield settlement resolves
```

Reason:
- Skill 3 is caused by qualifying DEATH_CONFIRMED outcomes during the Action;
- Skill 1 requires aggregation of the full Natural Action's outgoing repeat-passive damage;
- this prevents Skill 1's newly created Shield from being immediately consumed by Skill 3 in the same Action;
- it reduces explosive self-amplification and is easier to reason about.

This is Echo-specific gameplay ordering.

It must not be generalized into a global Reaction-priority rule for unrelated mechanics.

---

# 15. TWO ECHO REVERIES FIGHTING EACH OTHER

If Echo A and Echo B oppose each other:

- direct qualifying Action damage from A can update B's memory;
- direct qualifying Action damage from B can update A's memory;
- passive-generated repeat True Damage does not recursively trigger the other Echo's repeat passive;
- passive-generated repeat damage does not update Action-form memory;
- each Echo follows its own memory and Rage state;
- neither Echo is forced to retaliate against the other as target.

This prevents feedback loops.

# 16. RESOURCE IDENTITY

Echo is intentionally AE-hungry.

Current costs:

```text
Skill 1 linked settlement = 10 AE
Skill 2                   = 30 AE
Skill 3 linked settlement = 30 AE
Ultimate child Skill 2    = 0 AE
```

As a Mage:

```text
+7 AE after each actually completed Echo Natural Action
```

Echo is therefore naturally resource-negative when repeatedly activating his passive support/scaling effects.

This is intentional.

Design goal:
- high damage;
- strong scaling;
- fragile defensive profile;
- heavy team-resource demand;
- pressure to pair with Support / AE economy.

# 20. ECHO NATURAL-ACTION SETTLEMENT MODEL

Conceptually:

```text
Echo Natural Action begins
→ Basic / Skill / Ultimate executes
→ child Actions/effects belonging to it execute
→ qualifying outgoing Actual HP Damage creates one-layer passive repeats
→ lifecycle outcomes / qualifying True-Self deaths are observed
→ Skill 3 may settle once if eligible/payable
→ Skill 1 aggregates outgoing repeat-passive Actual HP Damage
→ Skill 1 may settle if eligible/payable/free
→ Action-linked Echo outcomes finish
→ Echo Natural Action completes
→ memory used for this Natural Action clears
→ free-Skill1 Natural-Action window advances if active
→ Mage AE regeneration grants +7 AE
→ new Action-form memory window remains active for the next actually performed Natural Action
```

This sequence defines Echo's intended dependency.

It does **not** define global priority among unrelated Reactions.
